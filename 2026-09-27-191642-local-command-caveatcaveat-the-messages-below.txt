  What was actually wrong (four separate bugs):

  1. Torn frames (the visual glitch). In Flycast, starting a render resets the
     Dreamcast's YUV video converter back to the top of the picture. KOS starts
     renders from an interrupt, which could land in the middle of a video
     frame's upload, so the rest of the frame was written over the top rows.
     Frames are now uploaded right after pvr_wait_ready(), where no render can
     start. The old build tore 7 of 257 intro frames; the new one tore 0 across
     the whole intro.
  2. Long stalls during playback. KOS only reads from disc at full speed when
     the destination buffer is 32-byte aligned. Ours weren't, so each 64 KB read
     became 32 separate one-sector reads. Some frames waited 200–480 ms for
     data, and the intro only managed about 13.6 fps. The buffers are aligned
     now.
  3. Bursts then freezes. The video clock only moved each time KOS refilled the
     audio buffer, in 0.37 s steps, and started 0.74 s early. So the video
     played about 9 frames in a rush, then froze. The clock now follows real
     time since the audio started.
  4. Power-attack clips were garbage in gameplay. The decoder keeps a matrix in
     an SH4 register bank that the game's rotated sprites also use, so the
     in-game renderer overwrote it. The decoder now reloads it every frame. This
     bug was older than today's changes.

  Decoding also moved to a background thread with a 3-frame buffer, so the game
  only spends about 0.4 ms per frame on video.
